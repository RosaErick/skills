# Activation design

Describe a concrete task and its discriminating condition. A noun such as CSV, React or API alone rarely identifies the needed workflow. Include a nearby exclusion when overlap is likely, and keep the entrypoint body consistent with its narrower description.

Test both directions: a task that needs the skill and a similar task that should proceed without it. Record missed activation, accidental activation and extra work induced after activation separately.

Make genuinely fragile correctness decisions visible, explaining the condition and consequence. Do not promote a preference to a MUST merely to improve uptake. Integrated examples help when they demonstrate a non-obvious boundary; avoid requiring every example to contain every pattern.
