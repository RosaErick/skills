# Plan a large change so work can continue

Read the objective, existing plan and affected architecture. Identify deliverable outcomes, dependencies, compatibility constraints and decisions that could change the route. Reuse known answers instead of starting a new discovery interview.

Make a compact map of milestones and the evidence that completes each. Use a diagram when dependencies are easier to understand visually. Split by meaningful vertical outcomes, migration boundaries or ownership, not a token budget or one-ticket-per-session rule.

For uncertain work, schedule a focused investigation or prototype with a decision it should resolve. Distinguish a genuine user decision from a reversible implementation choice. Include rollout and recovery where the change calls for them.

Save the map in the project's usual planning location when useful. If the request includes execution, begin the ready work and update progress as evidence changes the plan. Producing a chart is not a terminal step unless planning alone was requested.
