# Make a plan that supports delivery

Use the requested outcome, repository context and decisions already made. For a small task, a short sequence in the conversation may suffice. For substantial work, use the existing planning/documentation location and link the canonical spec or issue instead of copying it into competing sources of truth.

Break work into reviewable outcomes with meaningful dependencies. State what completes each step and which check will demonstrate it. Granularity should follow uncertainty and coupling, not a fixed minute estimate, task count or token budget.

Identify decisions that can be made now, investigations needed to choose, and actual approval boundaries. Make reversible implementation choices using context. Keep risk, migration and recovery details only where they affect execution.

When execution is requested, begin ready work and validate during implementation, updating the plan as evidence changes it. Do not defer all verification to the end or stop merely because the plan file is written. Report progress against outcomes rather than treating checkboxes as evidence.
