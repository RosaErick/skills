# Microcopy patterns

| Surface | Useful pattern | Check |
|---|---|---|
| Button | Concrete verb and object, such as “Save address” | Does the result match the label? |
| Empty state | Explain what is absent and offer a real next step | Is it empty data, a filter or missing permission? |
| Form error | Name the field problem and accepted input | Is that rule enforced by the product? |
| Background refresh | Preserve useful data and identify stale/failed refresh | Can the user retry without losing work? |
| Destructive confirmation | State the object and actual consequence | Is deletion reversible, and is that accurately described? |
| Success | Confirm the completed action | Has it really completed, or is it only queued? |
| Unknown failure | State the observed failure without guessing its cause | Is the proposed recovery available and safe? |

Localize the intent rather than translating rigid word counts. Avoid placeholders that resemble real credentials, fabricated product promises and technical error codes as the only explanation. Keep a support/debug identifier separate when it helps recovery.
